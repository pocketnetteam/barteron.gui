# Barteron nextgen — план работ

Обновлено 10.11.2026.

Barteron nextgen — новая версия Barteron по макетам редизайна. Функции остаются те же, что у старого приложения. Меняется интерфейс, и добавляется несколько предложений из макетов. Это мини-приложение Bastyon: своего сервера у него нет, объявления и профили хранятся в блокчейне Pocketnet.

## 1. Как устроено и что обязательно сохранить

**Устройство** (подробно — по коду старого приложения):

- Bastyon открывает Barteron в iframe с адреса `barteron.club`, id приложения `barteron.pocketnet.app`. Связь с Bastyon идёт через `BastyonSdk` (postMessage). Новая версия встаёт на тот же адрес и id и поэтому открывается и в новом Bastyon, и в прежнем.
- **Чтение** — RPC ноды через Bastyon: `getbarteronfeed`, `getbarteronaccounts`, `getbarteronoffersbyaddress`, `getbarteronoffersbyroottxhashes`, `getbarteronoffersdetails`, `getbarterondeals`, `getbarteroncomplexdeals`, `getuserprofile`, `getfromtotransactions`.
- **Запись** — транзакцию собирает и подписывает Bastyon, ключей приложение не видит. Виды записей: профиль (тип 104), объявление (тип 211), отзыв (комментарий), оценка, удаление.
- **Остальное тоже делает Bastyon:** фото, видео, чат, перевод PKOIN, баланс, история переводов, геолокация, камера, «Поделиться», жалоба. Список методов — в приложении A.
- **Внешние сервисы:**
  - `p2p.back.pocketnet.app/barteron` — уведомления в Telegram и VK, опрос;
  - coingecko и cryptocompare — курсы валют;
  - Nominatim и OpenStreetMap — поиск адресов и карта.

**Совместимость со старой версией** — обязательна. Пока работают обе версии, они видят и правят одни и те же объявления:

- Форматы транзакций 104 и 211 — точно как у старого клиента: поля `p.s1…p.s7` и JSON в `p.s4`. Новые поля можно только добавлять, старые не меняются.
- Маршруты и параметры ссылок остаются прежними, потому что ими уже делились в чатах: `/barter/:id`, `/barter/safedeal?…`, `/barter/moderation?…`, `/profile/:id`, `/category/:id`, `/barter/exchange/:id`, `/barter/search`.
- ID безопасной сделки строится по тому же алгоритму (`barteron.gui/src/js/safeDealUtils.js`, `IdHelper`). Иначе уже начатые сделки не откроются.
- Перед отправкой объявление проверяется на обязательные поля. 28.04.2026 объявление без категории уронило все ноды 0.22.20.

## 2. Решения

Приняты 09.11.2026:

| Вопрос | Решение |
|---|---|
| Стек | Vue 3.5, TypeScript, Vite, Pinia, vue-router, vue-i18n, TanStack Query. Карта — Leaflet. Тесты — Vitest и Playwright. Пакеты — pnpm. Так же устроен bastyon-nextgen, поэтому подходы и код можно переносить |
| Библиотека интерфейса | Своя дизайн-система по макетам, без ant-design |
| Шрифт Onest | Хранится в проекте, с Google Fonts не грузится: Google может быть недоступен через Tor и из РФ |
| Языки | ru, en, sr — как сейчас |
| Git | Пока только локальные коммиты в `main`, удалённого репозитория нет |
| `p2p.back.pocketnet.app` | Доступ дадут позже. До тех пор подключаем публичные адреса, как в старом приложении |
| Список сделок | Сделки, которые пользователь открывал или создавал на этом устройстве (подробнее — этап 8) |
| Автопродление | Без сервера объявление само не продлится: продление — транзакция с подписью пользователя. Поэтому при входе приложение предлагает продлить объявления, у которых истекает срок (подробнее — этап 4) |
| «Что продают рядом» | Делаем, когда дойдём до этапа 10; тогда же нужен макет |

Ещё не обсуждали:

| Вопрос | Предлагаю |

Сначала идут экраны, которые только читают данные: их можно проверять на настоящей сети, ничего туда не записывая. Первая запись — действия со своим объявлением на этапе 4, затем подача на этапе 5.

### Этап 0. Каркас проекта

- [x] Локальный git, ветка `main`.
- [x] Vite + Vue + TypeScript, линтер, форматтер, Vitest, Playwright.
- [x] Манифест `b_manifest.json` с тем же id, адресом и разрешениями, что у старого, включая `"develop": true`: прежний хост сверяет этот флаг со своим списком. Иконки.
- [x] Типизированная обёртка над `BastyonSdk` — только нужные методы (приложение A): `src/sdk/`.
- [x] Заглушка SDK, чтобы интерфейс открывался в обычном браузере. Фикстуры RPC добавим на этапе 2.
- [ ] Запуск внутри Bastyon:
  - [x] bastyon-nextgen: приложение открывается через «открыть своё приложение» с `https://localhost:5180`, получает язык, тему и сеть. Проверено 10.11 без входа в аккаунт;
  - [ ] bastyon-nextgen со входом: приложение получает адрес. Проверить вручную, тестовые ключи не используем;
  - [ ] прежний Bastyon (test.pocketnet.app).
- [x] Одна команда проверки: `pnpm check` — типы, линтер, форматирование, тесты. CI и деплой на тест — когда появится удалённый репозиторий.

Связь с настоящим `sdk.js` (копия из pocketnet.gui) проверяет e2e-тест с поддельным хостом в iframe.

Что выяснилось при запуске в bastyon-nextgen:

- CSP веб-версии хоста пускает фреймы и запросы только по https. Поэтому dev-сервер для открытия в Bastyon запускается по https: `pnpm dev:https`. В справке хоста (`help/ru/mini-apps-dev.md`) написано, что подойдёт и `http://localhost`, но на деле его не пускает CSP.
- Встроенный id `barteron.pocketnet.app` хост с localhost не принимает. Dev-сервер отдаёт манифест с id `barterondev.pocketnet.app`. Запись в сеть (`barteron.*`) хост разрешает только настоящему id — см. раздел 5, риск 6.
- Новый хост открывает `<адрес>/index.html` (поле `start_url` манифеста), прежний — корень `/`. Роутер переводит `/index.html` на `/`.
- Веб-версия хоста сообщает приложениям устройство `capacitor_android`: Capacitor определяется по `window.Capacitor`, а этот объект есть и в вебе. Баг хоста, Barteron это пока не мешает.

Готово, когда пустое приложение открывается в обоих Bastyon и получает адрес пользователя.

## 4. Правила для всех этапов

Взяты из принципов в `main.html`:

- **Честные статусы сети.** Публикация, отзыв и перевод — транзакции. Интерфейс показывает этап (отправлено → в блоке → готово), не изображает мгновенность и всегда даёт повторить.
- **Деньги — это PKOIN.** Цена всегда в PKOIN, рядом эквивалент в выбранной валюте. Если курс не загрузился, так и пишем, цену не прячем.
- **Аккаунт — это Bastyon.** Регистрации и паролей нет. Чат, кошелёк и уведомления живут в Bastyon, и каждый переход туда помечен значком ↗.
- **Темы:** светлая, тёмная и «как в системе». Тёмно-синей темы больше нет.

Плюс технические правила:

- Все тексты — через i18n на ru, en и sr. Тексты берём из макетов, а в макеты они пришли из старого приложения.
- Внешние запросы (курсы, карта, `p2p.back`) идут через fetch-туннель Bastyon там, где он есть, чтобы работал Tor. В старом приложении это `miniapp-service-worker.js`, в bastyon-nextgen — `src/mini-apps/core/fetch-tunnel.ts`.
- Каждый экран сверяется с макетом на ширине 1440 и 390, в обеих темах.
- Тесты:
  - модели, ID сделки, статусы сделки — unit-тесты;
  - восемь сценариев из `index.html` прототипа — e2e на заглушке SDK.

## 5. Открытые вопросы и риски

1. **Счётчики `getbarterongroups` могут не совпадать с выдачей.** В его SQL нет фильтра по статусу, поэтому в счётчики могут попадать снятые и истёкшие объявления. Проверить на настоящих данных на этапе 10.
2. **`p2p.back.pocketnet.app`.** Доступ дадут позже. По заметкам bastyon-nextgen, из РФ сервис недоступен, поэтому уведомления в Telegram и VK и опрос оттуда могут не работать.
3. **Два хоста.** Новый и прежний Bastyon могут по-разному отвечать на одни и те же методы SDK. Каждый этап проверяется в обоих.
4. **Списки в коде.** Бан-лист (около 700 адресов), гаранты и модераторы зашиты в код. Любое изменение — пересборка и деплой.
5. **Переключение сразу у всех.** Новая версия на barteron.club заменит старую у всех пользователей сразу, включая прежний Bastyon. Нужен план отката: оставить старую сборку под рукой.
6. **Запись в сеть из dev-сборки.** bastyon-nextgen выполняет `barteron.account`, `barteron.offer` и остальные записи только для id `barteron.pocketnet.app` (`assertBarteron` в `src/mini-apps/actions/barteron.ts`). Этот id закреплён за `barteron.club`. Значит, начиная с этапа 4 запись с localhost не проверить. Варианты — решить до этапа 4:
   - добавить Barteron во встроенном списке хоста тестовый адрес (`tscope`, например test.barter.pocketnet.app) и проверять запись на тестовом стенде;
   - разрешить в dev-сборке хоста настоящий id с localhost.

   Оба варианта — правки в bastyon-nextgen.
7. **Открытие с localhost в прежнем Bastyon.** Chrome не даёт странице с публичного адреса встроить localhost (Local Network Access): в e2e такой фрейм блокировался. Для bastyon.com и test.pocketnet.app браузер может спрашивать разрешение или блокировать. Проверить при запуске в прежнем Bastyon.
