# Запуск новой версии на barteron.club

Как выложить Barteron nextgen сначала на тест, потом на прод, и как вернуть старую версию. Написано 11.11.2026. Ничего из этого ещё не выполнялось: всё, что касается серверов, делается только с разрешения владельца проекта.

## Как выкладывается старая версия

По `.github/workflows/` репозитория [pocketnetteam/barteron.gui](https://github.com/pocketnetteam/barteron.gui):

|                       | Тест                      | Прод                   |
| --------------------- | ------------------------- | ---------------------- |
| Адрес                 | test.barter.pocketnet.app | barteron.club          |
| Ветка                 | `dev`                     | `main`                 |
| Раннер GitHub Actions | `test`                    | `mirror.barteron.club` |
| Папка на сервере      | `/docker/barter/`         | `/data/barteron/`      |
| SDK Bastyon           | test.pocketnet.app        | bastyon.com            |

Шаги workflow: Node 18, `yarn install`, `yarn build`, затем `rm -rf <папка>/*` и `rsync -ah ./dist/ <папка>/`.

На сервере PHP выполняет `index.php` для любого пути и подставляет в страницу теги превью ссылок. К ноде он ходит по адресу `http://proxy:8898/`.

## Что меняется для сервера

Ничего. Новая сборка повторяет старый набор файлов:

- `index.php`: страница приложения плюс теги превью. Его собирает плагин [build/index-php.ts](build/index-php.ts) из `index.html`, а `index.html` в сборку не попадает, как и раньше.
- `og.php` и `rpc.php`: превью для объявления, обмена, сделки, модерации и профиля. Исходники — [php/](php/). Ссылки и тексты те же, ошибки старых файлов исправлены (PLAN.md, этап 11).
- `b_manifest.json`, иконки (`b_icon.png`, `s_icon.png`, `m_icon.png`), `miniapp-service-worker.js`, `docs/`. Файлы приложения лежат в `assets/` (у старой версии были `js/`, `css/`, `img/`).

`api.php` не переносили: старый `og.php` его подключал, но ни разу не вызывал.

Требования: PHP 7.0 или новее с расширением curl, как и для старых файлов. Сборка: Node 20.19 или новее и pnpm 10. Старый workflow ставит Node 18, с ним новая версия не соберётся.

## Что нужно решить до запуска

1. **Где будет код и кто запускает сборку на раннерах.** Варианты: ветка в `pocketnetteam/barteron.gui` с заменой содержимого или новый репозиторий с доступом к тем же раннерам. Нужен доступ к раннерам `test` и `mirror.barteron.club`.
2. **Настройки сервера.** Нужно подтвердить, что любой путь, которого нет среди файлов, уходит в `index.php`, и узнать версию PHP. Превью проверены на PHP 7.4 и 8.3.
3. **Автор коммитов.** Сейчас в репозитории стоит `xen <xen@mail.com>`, автор не подтверждён.
4. **Правки нового Bastyon** ([HOST-TASKS.md](HOST-TASKS.md)), если он уже у пользователей:
   - п. 1–2: на телефоне нижняя панель хоста закрывает кнопки объявления и таб-бар Barteron, а кнопка закрытия накрывает «Избранное» (проверено 11.11 на основной сети);
   - п. 3: без него при включённом Tor не грузятся курсы, карта и поиск адресов.

## Порядок

### 1. Тестовый стенд

1. `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm build:test`.
2. Скопировать `dist/` в `/docker/barter/`, как это делает старый workflow.
3. Проверить:
   - превью: `curl -s https://test.barter.pocketnet.app/barter/<txid> | grep og:` — теги с названием объявления;
   - список паритета (PLAN.md, приложение B) в прежнем Bastyon (test.pocketnet.app) и в новом, на компьютере и телефоне. Прежний Bastyon до сих пор не проверялся ни разу (PLAN.md, риск 7);
   - запись в сеть: объявление, правка, снятие, профиль, отзыв, оценка, безопасная сделка с переводом, заявка на модерацию. Стенд работает с тестовой сетью, поэтому записывать можно, основная сеть не пострадает (PLAN.md, риск 6). Сначала проверить, разрешает ли хост запись приложению с тестового адреса;
   - ссылку из чата `…/application?id=barteron.pocketnet.app&p=<путь в hex>`: она должна открыть нужный экран.

### 2. Прод

1. **Снимок старой версии**, это и есть откат: `cp -a /data/barteron /data/barteron-old-<дата>`.
2. `pnpm build`: SDK с bastyon.com.
3. **Скопировать без `rm -rf`**: `rsync -ah ./dist/ /data/barteron/`. Старые `js/`, `css/` и `img/` остаются на сервере, поэтому у тех, кто держит старую версию открытой, она не сломается на подгрузке экрана. `index.php` заменяется, и каждое новое открытие получает новую версию. Старые файлы удалить через неделю.
4. Сразу после выкладки:
   - `curl -sI https://barteron.club/` → 200 и `Cache-Control: no-cache`;
   - `curl -s https://barteron.club/barter/<txid> | grep og:` → название объявления;
   - открыть в обоих Bastyon, на компьютере и телефоне: главная, объявление, профиль, сделка по ссылке из чата;
   - в логе ошибок PHP нет строк `Barteron link preview:`.

### 3. Откат

**Когда:** приложение не открывается в одном из Bastyon, не проходит запись в сеть или пользователи массово жалуются.

**Как:** `rsync -ah --delete /data/barteron-old-<дата>/ /data/barteron/`. Это возвращает старую версию целиком за секунды. Есть и другой путь: запустить старый workflow из `main` репозитория barteron.gui (кнопка Run workflow), результат тот же, только дольше из-за сборки.

**Что увидят пользователи:**

- Данные в сети общие. Объявления, профили, отзывы и сделки, созданные новой версией, старая показывает: форматы транзакций те же, новые поля только добавлены.
- Валюта, место и избранное хранятся на устройстве под старыми ключами и в старом формате, поэтому они сохранятся.
- Черновики, список сделок устройства, тема и отложенное продление лежат под новыми ключами. Старая версия их не видит, при повторном переключении они вернутся.
- Если новая версия открыта в момент отката, то при переходе на ещё не загруженный экран появится «Вышла новая версия». После перезапуска откроется старая.

## Проверка превью без сервера

```sh
pnpm build
node build/og-check.mjs --php <путь к php>
```

Скрипт поднимает поддельную ноду, отдаёт `dist/` через встроенный сервер PHP и проверяет 19 ссылок: объявление, обмен, сделку, модерацию, профиль, разметку в названии, ссылку с массивами, зависшую ноду. В сеть он не ходит. Его стоит прогнать на той версии PHP, что стоит на сервере.
